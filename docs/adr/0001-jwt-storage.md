# 0001. クライアントでの JWT の保存先

- 状態: 採用
- 日付: 2026-11-08
- 関連: issue #151（ログイン・新規登録・ログアウト UI と JWT 保持）

## 背景

ログイン後にサーバーから受け取る JWT を、リロード後も API 呼び出しで使えるように、
ブラウザのどこかに保持する必要がある。

- 課題（`kadai.md`）は「JWT を用いた認証」とだけ書かれており、保存先は指定されていない。
- 社内のセキュリティ方針（`.agents/skills/security`）には「フロントエンドの機密データはメモリのみ保持し、localStorage に保存しない」とある。
  ただし文脈はパスワードで、トークンまで含むかは明記されていない。
- サーバー側の実装は、有効期限 30 日の単一トークンを返す（方針文書の「アクセス 1 時間＋リフレッシュ 7 日」とは異なる）。
- #151 は「サーバー API の仕様変更なし」が条件のため、サーバーが Cookie を発行する方式は選べない。
- この課題の目的は学習であり、選択の理由を説明できることに価値がある。

## 検討した選択肢

| 案                 | 長所                                                                         | 短所                                                                            |
| ------------------ | ---------------------------------------------------------------------------- | ------------------------------------------------------------------------------- |
| A. メモリのみ      | XSS で永続的に盗まれにくい                                                   | リロードのたびにログインが必要。使い勝手が大きく落ちる                          |
| B. localStorage    | 実装が簡単。リロード・再訪後も保持される                                     | 30 日有効のトークンが残り続ける。XSS で読まれうる。社内方針に反する             |
| C. sessionStorage  | リロードに耐える。タブを閉じれば消える。社内方針の趣旨（長く残さない）に近い | XSS で読まれうる点は B と同じ。新しいタブでは再ログインが必要                   |
| D. httpOnly Cookie | JavaScript から読めず、XSS に強い                                            | サーバー変更（Set-Cookie、CORS の credentials、CSRF 対策）が必要。#151 の範囲外 |

## 決定

**C. sessionStorage** に保存する。保存処理は `client/src/auth/tokenStorage.ts` に閉じ込める。

## 理由

- 使い勝手（リロード後も維持）と、トークンを長く残さないこと（タブを閉じれば消える）の釣り合いが取れる。
- B より保持期間が短く、30 日有効のトークンが端末に残り続けることを避けられる。
- D が最も安全だが、サーバー変更が必要で #151 の範囲外。学習の観点では価値が高いため、別 issue（ステップ 6 のセキュリティ強化）として扱う。
- 保存先は 1 ファイルに閉じているため、後で D などに切り替える際の変更は小さい。

## 結果・トレードオフ

- XSS の脆弱性があれば、sessionStorage のトークンも読まれる。入力値の扱い（React のエスケープ、`dangerouslySetInnerHTML` を避ける）で防ぐ必要がある。
- 新しいタブやウィンドウでは、再ログインが必要になる。
- 今後の課題:
  - httpOnly Cookie 方式への移行を、別 issue として起票する（ステップ 6：Helmet・CORS と合わせて）。
  - 方針文書の有効期限の記載とサーバー実装（30 日）のずれを解消する。
  - 方針文書の「localStorage 保存禁止」が、トークンを含むかを明確にする。
