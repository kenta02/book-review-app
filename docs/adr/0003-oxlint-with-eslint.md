# 0003. lint は oxlint と ESLint を併用する

- 要約: lint は oxlint を一次チェック、ESLint を未対応ルールの担当として併用する
- 状態: 採用
- 日付: 2026-11-23
- 関連: issue #197、issue #198、PR #199

## 背景

lint の高速化と検出能力の補完を目的に、oxlint の導入を検討した。
検証（#197、oxlint 1.94.0）の結果は次のとおり。

- 併用しても、ESLint 単体の指摘は漏れなかった。
- 現状の規模（client 82・server 50 ファイル）では、速度の利点は出なかった。
  ESLint の起動時間が支配的で、併用の合計は ESLint 単体より短くならない。
- `import-x/no-unresolved` と `import-x/order` は oxlint が対応していない。
  `import-x/no-named-as-default-member` は oxlint 単体では検出できなかった。

## 検討した選択肢

| 案                       | 長所                                 | 短所                                    |
| ------------------------ | ------------------------------------ | --------------------------------------- |
| A. ESLint のみ（見送り） | 構成が単純                           | oxlint の運用を学べない                 |
| B. 併用する              | 検出漏れなく、役割分担の運用を学べる | 設定が 2 系統になる。現状は速くならない |
| C. oxlint に置き換える   | 実行が速い                           | 上記の import 系ルールの検査が失われる  |

## 決定

**B** を採用する。`lint` は oxlint、ESLint の順に実行し、
oxlint が担当するルールは `eslint-plugin-oxlint` で ESLint 側を無効化する。

## 理由

速度だけが目的なら見送りが妥当だが、役割分担の運用の学習・確立と、
将来の規模拡大を見据えて導入する。

## 結果・トレードオフ

- ルールの設定は `.oxlintrc.jsonc` と ESLint 設定の 2 か所になる。
- oxlint を実行しないと、ESLint 側で無効にしたルールの検査が抜ける。
- `@oxlint/migrate` は現行の設定を正しく変換できないため、設定は手書きで保守する。
- 今後の課題: react-hooks ルールの適用範囲（#200）。
