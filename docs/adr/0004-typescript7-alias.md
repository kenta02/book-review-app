# 0004. TypeScript 7 は型チェックにだけ別名で併用する

- 要約: TypeScript 6.0.x を残し、TS 7 を別名で併用して check-types だけに使う
- 状態: 提案中
- 日付: 2026-11-27
- 関連: PR #125、PR #140、PR #207

## 背景

型チェックとビルドの高速化を目的に、TypeScript 7.0（7.0.2）の導入を調査した
（2026-11-23）。

- 本プロジェクトのコードは、TS 7.0.2 の `tsc --noEmit` が server・client ともエラー 0。
- TS 7 の `typescript` パッケージには Compiler API がなく、
  ts-node / typedoc / typescript-eslint が動かない。
- PR #125 でルートを 7.0.2 に更新したが、ts-node の初期化が失敗し、
  PR #140 で 6.0.3 に戻した。
- 現在の版は不揃い（ルート 6.0.3 / server 6.0.2 / client 5.9.3）。

## 検討した選択肢

| 案                            | 長所                                       | 短所                           |
| ----------------------------- | ------------------------------------------ | ------------------------------ |
| A. `typescript` を 7 に上げる | 構成が単純で、全体が速くなる               | ts-node などが動かない         |
| B. 6.0.x ＋ TS 7 を別名で併用 | 既存ツールを保ちつつ型チェックを速くできる | TypeScript を 2 系統で管理する |
| C. 見送る                     | 変更が不要                                 | 高速化できない                 |

## 決定

（提案）**B** を採用する案。全 package.json の `typescript` を 6.0.x に統一し、
`typescript-native`（`npm:typescript@7.0.2`）を追加して、
server の `check-types` だけを TS 7 で実行する。

## 理由

A は既存ツールが動かない。型チェックは TS 7 で通るため、C にする必要はない。

## 結果・トレードオフ

- ts-node / typedoc / ESLint は TS 6 のまま使う。`build` は既定を変えない。
- 次の項目は未検証で、確認してから採用を判断する。
  - 併用構成での typescript-eslint の実行
  - pnpm での別名の bin 解決（検証は npm で実施した）
- TS 7.1 の安定 API と各ツールの対応状況を見て、再検討する。
