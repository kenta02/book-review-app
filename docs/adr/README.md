# ADR（Architecture Decision Record）

設計上の重要な意思決定を、「なぜそう決めたか」まで含めて残すための記録です。
コードを見れば「何をしたか」は分かりますが、「なぜそうしたか」「他に何を検討したか」は残りません。
後から参加する人や、将来の自分が迷わないために、判断の背景を短く書き残します。

## 読み方

- **まずこの README の一覧だけを読む。** 「現在有効」の表で、今守るべき決定と要約が分かる。
- 理由や検討した他案が必要なときだけ、該当する ADR の本文を開く。
- 「過去」の表は、経緯を調べるとき以外は読まなくてよい。

## 書くタイミング

- 後から変えるのにコストがかかる選択をしたとき（認証方式、保存先、ライブラリ採用など）
- 複数の選択肢で迷い、比較して決めたとき
- 方針や規約と異なる判断をしたとき

## ルール

- ファイル名: `NNNN-短い題名.md`（連番、英小文字とハイフン）
- 書式は [`0000-template.md`](./0000-template.md) を使う
- 一度決めた ADR の本文は書き換えない。変更するときは新しい ADR を作り、古い ADR の状態を「置き換え済み」にして新しい ADR へリンクする
- ADR を追加・状態変更したら、**この README の一覧も同じ PR で更新する**（一覧と本文のずれを防ぐ）
- 「要約」は、ADR 先頭の「要約」行と同じ文にする（1 文、60 字程度まで）

## 状態の種類

| 状態         | 意味                       | 一覧での置き場所 |
| ------------ | -------------------------- | ---------------- |
| 採用         | 決定済みで、現在の方針     | 現在有効         |
| 提案中       | 検討中。まだ決まっていない | 提案中           |
| 却下         | 検討したが採用しない       | 過去             |
| 置き換え済み | 後の ADR で方針が変わった  | 過去             |

## 一覧の上限

- 「現在有効」は **15 件まで** を目安にする。超えそうなら、分野（認証、API、UI など）ごとに表を分ける。
- 「過去」は上限なし。末尾に追記していく。
- 件数が少ないうちは、この運用で十分。5 件を超えたら、索引の自動生成なども含めて見直す。
