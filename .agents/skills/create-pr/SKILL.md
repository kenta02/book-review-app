# Pull Request 作成

## 手順

1. `git status` / `git log <base>..HEAD` / `git diff <base>...HEAD` で、PR に含まれる全コミットと差分を確認する。
   ベースは通常 `develop`（`hotfix/` のみ `main`）。
2. ブランチ名がブランチ戦略に沿っているか確認する（`feature/<フェーズ>-<機能名>` など）。
3. 未 push なら、push してよいかユーザーに確認してから push する。
4. タイトルと本文を作る。

   - タイトル: `[TYPE] 説明（日本語）`（TYPE はコミット規約と同じ）。70 文字程度まで。
   - 本文は `.github/pull_request_template.md` の見出しに従う。
     - 変更の目的 / 詳細説明 / テスト方法 / 関連 Issue / スクリーンショット（UI 変更時）/ チェックリスト
   - 次を必ず含める: 変更ファイルの概要、**変更していないもの**、実行した確認（lint / check-types / test:ci の結果。成功・失敗とも）、人間による確認が必要な点。
   - 関連 Issue があれば `Closes #<番号>` で紐づける。

5. **作成前に、タイトルと本文をユーザーへ提示して確認を取る。**
6. 確認後、`gh pr create --base <base> --title ... --body ...` で作成する。
   ラベルは `.github/labeler.yml` が自動付与するため、手動では付けない。
7. 作成した PR の URL を報告する。

## 守ること

- 秘密情報・内部パス・個人情報を本文に書かない。
- 1 つの PR に複数の目的を混ぜない。大きい場合は分割を提案する。
- 作業途中なら Draft（`--draft`）で作成することを提案する。
- 末尾に付ける表記（`🤖 Generated with ...` など）は、使っているツールの指示に従う。
