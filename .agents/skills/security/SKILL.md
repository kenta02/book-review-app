# セキュリティ・認証

本書籍レビューアプリのセキュリティポリシーと実装ガイドラインです。

## 認証・認可

- **認証方式**: JWT を使用。
- **トークン送信**: `Authorization: Bearer <token>` ヘッダーで送信。
- **トークン有効期限**: アクセストークン 1 時間、リフレッシュトークン 7 日。
- **認可チェック**:
  - ユーザーは自身のレビュー・評価のみ編集・削除可能。
  - 管理者のみ他のユーザーのレビューを削除可能。
  - ログイン必須で書籍データアクセス（一部は読み取り可能な設定も検討）。

## 暗号化・データ保護

- **HTTPS**: 本番環境では必須。開発環境でも localhost 以外では SSL 設定。
- **パスワード永続化**:
  - バックエンド：bcrypt（cost: 12）でハッシュ化。
  - フロントエンド：メモリのみ保持（localStorage に保存しない）。
  - 送信時は HTTPS 上で暗号化。
- **機密データ**: API キー、DB 接続文字列は環境変数で管理（`.env.local`）。

## API セキュリティ

- **入力バリデーション**: `express-validator` または Zod で全入力をサニタイズ。
- **レート制限**: ブルートフォース対策として `/api/auth/login` に rate limiter を設定。
- **CORS**: `server/src/middleware/cors.ts` でホワイトリストを管理。許可オリジンを明示的に指定。
- **エラーハンドリング**: 実装詳細を隠す（例: 「ユーザーが見つかりません」ではなく「認証に失敗しました」）。
- **SQL インジェクション対策**: ORM（Sequelize）を使用し、プレースホルダ構文を厳守。

## ロギング・監査

- 敏感な操作（ログイン、パスワード変更、データ削除）は監査ログに記録。
- ログには個人識別情報（パスワード、メールアドレスなど）を含めない。
- ログファイルはサーバーサイドで保護され、定期的にローテーション。

## 依存関係・パッチ管理

- 脆弱性スキャン：定期的に `npm audit` を実行し、重大脆弱性は即座に対応。
- 更新ポリシー：セキュリティパッチは優先度高、その他は月次レビュー。
