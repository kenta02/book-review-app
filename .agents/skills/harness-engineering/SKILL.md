# ハーネスエンジニアリング

## 1. ハーネスエンジニアリングとは

テストハーネスは、アプリケーションの挙動を安定して検証するための
自動化された「実行インフラ」です。テストデータ、モック／スタブ、
フィクスチャ、テストランナー、CIジョブの構成を含み、手動作業なしで
信頼性の高い検証を可能にします。

## 2. 目的

- 開発サイクルを高速化しつつ品質を担保
- 回帰テストの信頼性向上
- 環境依存性・サイドエフェクトを分離
- 既存 CI へのテストタイプ（単体・統合・E2E）を整備

## 3. 適用範囲

- `client` / `server` のテスト実行パイプライン設計
- ユニットテスト / 統合テスト / E2E テスト用の共有 fixtures 体系
- テスト向けモックやシミュレーションデータの構造定義
- CI/CD でのテスト依存関係、並列実行、フラッカーテスト対応

## 4. 実装ガイド

1. テストケースを機能単位で整理
   - ファイル名とディレクトリを一貫化
   - `*.test.ts(x)` を基本

2. モックとスタブを明確に分離
   - `msw` や `sinon` など利用
   - ネットワーク依存は API 層で抽象化

3. テストデータはフィクスチャ化
   - `tests/fixtures` など統一パス
   - リテラル埋め込みは最小化

4. CI ジョブで段階的実行
   - `lint` → `unit` → `integration` → `e2e`
   - 失敗時に速やかにフィードバック

5. フラッカーテストの検出
   - 同一テストの再実行チェック
   - `--runInBand` / `--repeatEach` で安定性評価

6. ローカル再現性の担保
   - リポジトリ内の `docker-compose.test.yml` で DB 起動など
   - `npm run test:ci` がローカルでも通る状態

## 5. 成果物の期待値

- 新しいテストを追加したときの PR で「テストハーネスの修正項目」が明示的
- CI で再現できない不安定性の原因調査時間削減
- 既存テストの実行時間が適切に管理され、スローダウンを防止
