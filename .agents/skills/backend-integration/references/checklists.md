# Backend Integration - 実装チェックリスト

新しい API エンドポイントを追加する際にご確認ください。

## エンドポイント設計

- [ ] RESTful 標準に従っている（GET, POST, PUT, DELETE の使い分け）
- [ ] リソース名は複数形（`/api/books` ✓、`/api/book` ✗）
- [ ] 階層関係を適切に表現（`/api/books/:id/reviews`）
- [ ] ステータスコードを正しく返している（200, 201, 400, 401, 404, 500 など）

## 認証・認可

- [ ] ログイン必須エンドポイントに `verifyToken` ミドルウェアを追加
- [ ] 権限チェックを実装（自身のデータのみ編集可など）
- [ ] エラーレスポンスに個人情報を含めない

## バリデーション

- [ ] リクエストボディをバリデーション（`express-validator` または Zod）
- [ ] 型チェックを実装
- [ ] エラーメッセージは明確に

## エラーハンドリング

- [ ] 統一イタなエラーレスポンス形式（`{ error: string; details?: any }`）
- [ ] 予期しないエラーは 500 を返す
- [ ] ログに詳細記録、クライアントには要約を返す

## フロントエンド連携

- [ ] API クライアントを `src/api/` に作成
- [ ] `axios` で API を呼び出す
- [ ] トークン自動リフレッシュ機能を実装
- [ ] ローディング・エラー状態を処理

## テスト

- [ ] API エンドポイントのユニットテスト実装
- [ ] 認証・認可テストを実装
- [ ] エラーハンドリングテストを実装

## CORS・セキュリティ

- [ ] CORS ホワイトリストを明示的に指定
- [ ] 本番環境でのオリジン確認
- [ ] rate limiting を適切に設定
