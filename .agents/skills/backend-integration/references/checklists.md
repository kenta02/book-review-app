# Backend Integration - 実装チェックリスト

新しい API エンドポイントを追加する際にご確認ください。

## エンドポイント設計

- [ ] HTTP メソッドを使い分けた（GET, POST, PUT, DELETE）
- [ ] リソース名は複数形にした
- [ ] ステータスコードが適切（200, 201, 400, 401, 403, 404, 409, 500 など）
- [ ] `server/src/openapi.yaml` を更新した

## 認証・認可

- [ ] ログインが必要なルートに `authenticateToken` を付けた
- [ ] 管理者専用のルートに `requireAdmin` を付けた
- [ ] 本人のみの操作は、service 層で確認した

## バリデーション・エラー

- [ ] `server/src/validators/` で入力を検証した
- [ ] 入力エラーは controller で `400`、業務エラーは `ApiError` で返した
- [ ] エラーメッセージは英語（画面の表示は日本語）
- [ ] 予期しないエラーは 500 を返し、詳細はログに残した

## フロントエンド連携

- [ ] `client/src/api/apiClient.ts` に呼び出しを追加した
- [ ] モック API をそろえた
- [ ] `client/src/types/` の型をサーバーと合わせた
- [ ] ローディングとエラーの状態を処理した

## テスト

- [ ] 正常系と異常系（バリデーション違反）を追加した
- [ ] 認証を伴う場合は 401 と 403 を追加した
